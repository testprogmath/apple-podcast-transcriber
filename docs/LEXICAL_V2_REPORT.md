8. **Algorithm:** process each contiguous Han run independently, preserve valid explicit study claims, then compare complete candidate paths by dynamic programming. Every token carries sentence-local Unicode code-point `[start,end)` spans. Source text is never normalized or rewritten.
9. **Candidates:** explicit study chunks; exact bounded CC-CEDICT headwords; narrowly evidenced botanical compounds; existing jieba spans; individual Han characters.
10. **Selection:** singles score 1; jieba spans `2*length-1`; exact dictionary spans `3*length-1`; botanical compounds `3*length+1`. Subtract 3 from a non-jieba whole dictionary span if it can swallow two exact multi-character words. DP maximizes summed path score; ties prefer shorter current spans deterministically. Existing explicit study leftmost/longest precedence is retained, separately from generic candidate scoring.
11. **Not global longest-match:** competing paths are compared. With controlled overlapping entries, `中国 | 人民` beats a weak `中国人民`; explicit study `中国人民` still wins. Strong chunks such as 打电话 beat fragments. Not every long dictionary phrase is protected.
12. **Composition/limits:** initial productive suffix is only 花. The 2–4-character base must have a literal botanical dictionary gloss beginning with a supported flower noun (peony, rose, orchid, chrysanthemum, azalea, jasmine, hibiscus, camellia, magnolia, lotus, lily, tulip or daffodil; optional constrained botanical modifiers). 花 must explicitly have the gloss `flower`. `rose-colored` and arbitrary `电话 + 花` do not qualify. No Chinese peony strings are hardcoded. One narrow exception to study priority rejects a dictionary-absent study suffix starting *inside* such an evidenced compound (`丹花` inside `牡丹花`); aligned `牡丹` and dictionary-backed claims retain priority. This is a heuristic lexical safeguard, not general validation of study material or a morphology parser.
13. **Performance:** CC-CEDICT bounded headwords/glosses indexed once per Dictionary instance; no scan of all dictionary entries per character and no SQL per candidate. Candidate length capped at 12; bounded decomposition checks, approximately O(n*L²) with fixed L, O(n) DP memory. One O(dictionary-size) initial load adds a process-local map. Warm tokenizer probe: 135,000 characters / 75,000 tokens in 0.439 seconds on this machine (not a production latency guarantee). See JSON evidence.
