It lacked a Mini App library, creation and rename. No prerequisite branch or cherry-pick was needed.
6. **Architecture:** shared source adapters produce ReaderDocument; existing services and renderer remain shared. Added library/create/rename around that renderer, not a second Reader. File metadata is no longer interpreted as a study-material directory.
7. **Sources:** `podcast`, `pasted_text`, `file`. Explicit text/file creation gets a new identity even for identical content. No web importer or fake podcast identity.
8. **Migration:** additive nullable SQLite `updated` and `last_opened`; existing updated dates backfilled from created; legacy `text` becomes `pasted_text`. New rows initialize updated. Re-saving podcast output preserves a user rename. Existing IDs, integration keys and translations remain intact.
9. **Library:** authenticated metadata-only latest 100 documents; most recent opened/created first, ID tie-break; title, human source label and date. Empty state allows immediate creation. No full text, segmentation or LLM work during list retrieval.
10. **Telegram `/reader`:** opens the library without requiring a podcast. Existing Telegram plain-text/file creation is preserved through shared adapters.
11. **URLs:** `/reader/` opens library; existing `/reader/?doc=...` opens its document. URL navigation survives refresh; document view has a Reader back link.
12. **Paste:** optional title, normal textarea paste; trims outer whitespace only, preserves internal text/Unicode; existing Chinese-content and 200,000-character validation retained. Failed creation retains input.
13. **Clipboard:** explicit click only, feature detection, graceful missing/denied fallback; existing textarea text is retained on failure.
14. **Files:** `.txt`, `.md`, `.markdown`, case-insensitive; browser picker and Telegram use the same adapter. Strict UTF-8, optional BOM; rejects empty, invalid encoding and binary control content. Durable data is text, not an uploaded blob.
15. **Limits:** 512 KiB decoded file bytes, chosen to fit base64 JSON under the existing 1 MiB HTTP-body limit. Encoded and decoded sizes checked; Telegram known size checked before download; shared adapter checks actual bytes. Existing character limit also applies.
16. **Markdown:** conservative removal of headings, lists/quotes, fence markers, links and emphasis; readable content retained. Not a full Markdown renderer. HTML-looking text stays inert.
17. **Titles:** explicit cleaned single-line title up to 120 characters; deterministic first nonempty text line up to 60 characters when absent. File title from sanitized basename stem; no client directory paths persisted.
18. **Rename:** authenticated title-only PATCH; updates title/updated date, not identity, source, translations or keys. Frontend changes title without resetting baskets/current document view. No new reading-position feature.
19. **Hanly:** existing standalone `reader:<document-id>` key remains stable across reopen/rename/upload. Rename alone makes no remote call; existing Hanly client applies current title on the next explicit upload, preserving UUID and Notes ownership.
20. **Mosaic:** existing Reader-specific stable key retained, separate from podcast study-pack snapshot. Existing pack snapshot/name is not automatically renamed.
21. **Translation:** existing exact material, cached result, then on-demand generation precedence; imports never eagerly translate. Cache survives rename/reopen.
22. **Pronunciation:** existing word speech and single sentence audio control retained; standalone sources use system Mandarin TTS normally.
23. **Podcast audio:** original recording and timing path unchanged; original audio used when available, existing TTS fallback otherwise. Existing audio regression tests pass.
